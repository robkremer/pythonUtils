util.persistence.serialize module¶

This module represents a Strategy pattern (Gamma et al) class (SerializationStrategy) that serves to serialize and unserialize Python objects with proper support for multiple references to the same object. Thus, if [a, b] where a is b is stored, then when [a, b] is read back, a is b will still be true (although the read-back a will not likely have the same id as the original a).

This module contains the following classes/functions:

class:

SerializationStrategy: The main class programs use to write and read persistent data to files or URLs. It serves both as an abstract superclass to all specific strategies/protocols (eg: XML, JSON) and it’s class methods support easy access to these specific strategies.

class:

Serializable: If you want to store user-defined classes, you must include this abstract class as a superclass. This obligates defining the Serializable.getInstantiationInfo() method.

class:

InstantiationInfo: A data class the is returned by the above method.

class:

ParamInfo and PropertyInfo: A data class that forms part of the information in InstantiationInfo.

class:

strdict: A direct sublclass of dict that restricts keys to str. Many of the serialization protocols use such a structure and you can significantly reduce the size of files by storing dictionary-type data using this class rather than dict whenever you have a dict with string keys.

func:

getInstantiationInfo(): A utility function to retrieve the instantiation information from a Serializable subclass.

SerializationStrategy is an abstract class that supports various storage formats such as XML or JSON through concrete subclasses. Other possibilities are plist, marshal, and pickle. This an application can hold a reference to SerializationStrategy witch could, for example, be either a concrete SerializeXML or SerializeJSON and use the write() and read() methods to write/read data in the relevant data formats.

Object types supported:

  • int

  • float

  • str

  • list

  • tuple

  • set

  • dict

  • strdict: a subclass of dict restricted to str keys.

  • Any properly implemented subclass of Serializable.

Any user-defined class to be stored using SerializationStrategy must inherit from Serializable, which obligates it to override the getInstantiationInfo() method. This method must return a InstantiationInfo object, which has five properties:

cls:

[type] The class of the object

conArgs:

[Optional[list[ParamInfo]]] Information about the each of the positional arguments to the object’s constructor.

conKWArgs:

[Optional[list[ParamInfo]]] Information about the each of the keyword arguments to the object’s constructor.

postconSetters:

[Optional[list[PropertyInfo]]] Information about each of the updates to be done immediately after the constructor is called (other “sibling” objects may not have been created yet).

finalSetters:

[Optional[list[PropertyInfo]]] Information about the each of the updates to be done after ALL of the “sibling” objects have been created.

where ParamInfo and PropertyInfo are data classes defining:

name:

[str] The name of the parameter in the class’s constructor (__init__()).

typ:

[type] The fully qualified class name.

getter:

[getter: Optional[Callable[[Serializable], SerializableType]]=None] A function taking a this object as a parameter and returning a value to be passed to the constructor. If this is None or not given, name will be taken to the a property of this object and will be taken as the value to pass to the constructor.

setter:

(PropertyInfo only) [Optional[Callable[[Serializable, SerializableType], None]]=None] A function taking two arguments: a newly constructed version of this object, and the object produced by getter(). This is applied on restoration of the object either immediately after the constructor or after all objects entailed by the construction of the object are complete. If this is None or not given, name will be taken to the a property of this object that property will be updated with the restored getter() object at the appropriate time.

Programs using concrete SerializationStrategy objects have the following interface (the “public” methods without prefix underscores):

  • writex(): (class method) Looks up a protocol to write an object to a file or URL.

  • readx(): (class method) Looks up a protocol to read an object from a file or URL.

  • tostringx(): (class method) Looks up a protocol to convert an object to a serialized string.

  • fromstringx(): (class method) Looks up a protocol to convert a serialized string to an object.

  • getAvailableStrategies(): (class method) Retrieves basic information about all known available concrete persistent strategies.

  • write(): Writes an object to a file or URL.

  • read(): Reads an object from a file or URL.

  • tostring(): Converts an object to a serialized string.

  • fromstring(): Converts a serialized string to an object.

  • defaultExtension(): Returns the default file extension for the strategy.

  • protocolName(): Returns the name of the concrete strategy.

  • protocoVersion(): Returns the version of the concrete strategy in n.n… form as a string.

  • header: A dict containing header info from the last file, URL, or string read.

  • appName: Apps should set this string to the name of the app at initialization. To be recorded in file headers.

  • appVersion: Apps should set this string to the version of the app at initialization. To be recorded in file headers.

  • version: (read only) The <appVersion>:<serializationVersion>:<protocolVersion> string.

class util.persistence.serialize.SerializationStrategy¶

Bases: ABC, Generic

A Strategy pattern class designed to save objects in a manner that allows for multiple storage formats (eg: XML, JSON, etc). This class proposes to support build-in data types: int, float, bool, str, list, dict, tuple, set, as well as any (properly constructed) user-defined subclass of Serializable.

For subclass (concrete protocol) developers:

The T generic type is the artifact type used by the concrete protocol (subclass). For example, for XML implemented with etree package, it’s Element and for JSON implemented with the json package, it’s Union[dict, list, int, float, bool, str].

Subclasses (defining specific strategies) must override (minimally) the following abstract methods:

  • _tostring(): given an eligible object, return a serialized str version of the object.

  • _fromstring(): given a serialized str, return the corresponding Python object.

  • _setAttr():

  • _getAttr():

  • _setKVPair():

  • _getKVPair():

  • _getKVPairs():

  • _appendItem():

  • _getItems():

  • _encodeStr(): for a str object, return the corresponding T object.

  • _decodeStr(): for a T object, return the corresponding str object.

  • _encodeList(): return the T object corresponding to an empty list.

  • _decodeList(): for a T object representing a list, return a list of T objects.

Subclasses may override the following concrete methods (by default they are implmented in terms of the methods above):

  • _encodeInt():

  • _decodeInt():

  • _encodeFloat():

  • _decodeFloat():

  • _encodeBool():

  • _decodeBool():

  • _encodeTuple():

  • _decodeTuple():

  • _encodeSet():

  • _decodeSet():

  • _encodeDict():

  • _decodeDict():

  • _encodeStrdict(): Encode a strdict object;

    useful as so many protocols (eg: JSON, plist) have “native” dictionaries restricted to str keys.

  • _decodeStrdict(): Decode a strdict object

  • _encodeSerializable():

  • _decodeSerializable():

Subclasses should NOT override the following methods as they encapsulate all the housekeeping involved in keeping track of object pointers. However, subclasses should USE these methods (rather than the _encode*() and _decode*() methods above when storing objects for that same reason:

  • _encode_():

  • _decode_():

peekType(url: str, mode: str = 'w', **kwargs) → type¶
Parameters:

  • url (str) – The source URL to inspect.

  • mode (str) – Passed through to fixURL() exactly as read() does.

  • kwargs (dict[str, Any]) – Passed through to _fromstring().

Returns:

The class of the top-level (“root”) object stored at url.

Return type:

type

Raises:

  • TypeError – If the declared type name can’t be resolved to an actual class.

  • ValueError – If the URL’s scheme isn’t “file”, “http”, or “https”.

Learns what’s stored at url WITHOUT constructing it – or anything it contains: parses just far enough to read the top-level object’s declared “type” attribute, using exactly the same structural primitives (_fromstring(), _getKVPair(), _getAttr()) that _decode_() itself uses for that same lookup; it simply stops there instead of going on to call any constructor. _fromstring() returns a lightweight strategy-specific representation of the parsed document (an ElementTree.Element for XML, a plain dict for JSON) – turning bytes into that shape, not into Serializable objects, so nothing in this method has any side effect on the object graph the document describes.

This exists so callers who only need to know what a file is (e.g. Application.openWindow(), which must tell a Model file from a SNGView file before deciding what to do) don’t have to fully read – and thereby construct and register – the object just to find out.

Important

This default implementation is only correct for a strategy whose _fromstring() returns a representation that doesn’t itself construct any Serializable object – true of XMLSerializationStrategy and JSONSerializationStrategy, both of which only ever produce an inert data structure at the _fromstring() stage. A strategy for which parsing and object construction are inherently fused – e.g. one based on Python’s pickle protocol, where finding a class name ordinarily means unpickling – MUST override this method with its own cheap, format-specific technique (for pickle, overriding Unpickler.find_class() to record the class and raise before any GLOBAL/REDUCE opcode actually builds anything is the standard trick). Inheriting this default for such a strategy would silently make peekType() just as expensive, and just as side-effecting, as a full read() – defeating its purpose.
