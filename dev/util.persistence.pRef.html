exception util.persistence.pRef.CircularReferenceError¶

Bases: Exception

Raised when a PRDb document (directly or via a chain of other documents currently being read) ends up referencing its own URL while that URL’s PRDb._read() is still in progress. Without this check, such a document would otherwise send PRDb.__new__() into unbounded recursion – each nested attempt to load the same not-yet-finished URL passing every earlier guard (it’s not yet in AllDBs; the file exists; it’s not the top-level _reading call) – until the interpreter’s call stack is exhausted.

class util.persistence.pRef.PRObject(db: DBT, **kwargs)¶

Bases: Serializable, Dirtyable, Generic

An object with an immutable integer ID and a mutable name.

__init__(db: DBT, **kwargs) → None¶
Parameters:

  • db (PRDb) – The db to which this object will belong.

  • kwargs (Any) – Passed on to super().__init__(). PRObject is often one link in a longer chain of cooperative __init__ calls – eg: a class combining AbstractGraph’s AGRelation with a sibling class via multiple inheritance (see sn.model.model.Relation) reaches PRObject through more than one base. Calling super().__init__(**kwargs) here (instead of simply returning) ensures whatever comes after PRObject in that particular class’s MRO – eg: AttributedObject, for a Relation or plain GraphObject – still gets initialized, exactly once, with the constructor arguments meant for it, even though PRObject itself has no use for them.

Raises:

  • PermissionError – If the DB is write locked.

  • TypeError – If the value is not of type PRObject.

  • MemoryError – if the DB has been deleted.

Note:

This used to call Serializable.__init__(self) and Dirtyable.__init__(self) directly, up here, before the super().__init__(**kwargs) call below. Serializable has no __init__ of its own so that call was a no-op, but the explicit Dirtyable call meant Dirtyable got initialized via a hardcoded direct call rather than via this class’s cooperative super() chain – and, since a class combining PRObject with something listed after Dirtyable in its own MRO (eg: sn.view.graphics.vobjects.VObject, which also mixes in ErrorReportingObject) relies on that same chain to reach the classes after Dirtyable too, this dead end silently meant ErrorReportingObject.__init__() – and anything else listed after Dirtyable – never ran at all for any such object. Removing the explicit calls and letting Dirtyable (now itself cooperative – see its own __init__) be reached exactly once via super() below fixes that for every current and future user of this class, not just this one case.

class util.persistence.pRef.PRDb(url: str, mode='w', memoryResident: bool = True, _reading: bool = False)¶

Bases: Serializable, Subject, Dirtyable, Generic

A dict-like object whose keys are restricted to int and values to PRObject.

__getitem__() and related lookup methods accept either:

  • an int -> direct key lookup by ID

  • a str -> lookup by PRObject.name (raises DuplicateNameError if ambiguous)

METHODS PURPOSELY NOT IMPLEMENTED:

  • __setitem__() (index assignment) is NOT implemented. Instead, the constructor

    of PRObject calls PRDb._register() to obtain an id and insert itself into the PRDb.

  • update()

AllDBs: ClassVar[dict[str, PRDb]] = {}¶
aliases: ClassVar[dict[str, str]] = {}¶

Other URLs for DBs – eg: their old names, or where they were before they were moved – and the URLs they stand for (see resolveURL()): eg, “sn:/sn.xml” -> “sn:/sn”. One ending in “/” stands for everything under it (see _alias()).

namedURLs: ClassVar[dict[str, Callable[[], str]]] = {}¶

Names – pseudo-URLs, eg: “sn:/baseRules” – of DBs whose actual URLs are only known when the program runs (eg: a temporary copy of a file that comes with it), and how to get each one’s URL – reading the DB, if need be (see resolveURL()). A reference to one is written as its name (see relativeURL()).

_namesOf: ClassVar[dict[str, str]] = {}¶

The names of the namedURLs that have been resolved, by their actual URLs.

readProgress: ClassVar[Callable[[PRDb, int], None] | None] = None¶

If set, called as a file’s objects are read – every READ_PROGRESS_STEP of them – with the DB being read and how many of its objects have been read so far (eg: to show a progress bar: its nextID is about how many there’ll be).

READ_PROGRESS_STEP: ClassVar[int] = 250¶

How many objects are read between calls of readProgress.

_readingURLs: ClassVar[set[str]] = {}¶

URLs for which a PRDb._read() call is currently in progress (see __new__() below). A URL is added just before its _read() starts and removed as soon as that call returns or raises. __new__() checks this set before starting a new read so that a document which (directly, or through a chain of other documents it references) ends up loading its own URL again fails fast with a CircularReferenceError instead of recursing until the stack overflows: AllDBs alone can’t catch this, since a URL is only added there after its read completes.

classmethod readFile(url: str, mode='w') → Any¶

Read the object in the file (or at the URL) url – usually a PRDb, but not necessarily – and return it. Use this rather than SerializationStrategy.readx() to read a PRDb, as it takes care of files that have been copied or moved:

A copied or moved file still has its old URL in it. That’s found out first (without reading the file), so that while it’s read it’s taken as being the file it was actually read from – never confused with the original (which may be open) – and so are its references to files that were next to it, if they’ve been copied along with it (see _relocate()). Its previousURL is the URL it was copied from (written in the header the next time it’s saved).

classmethod _isValidID(s: str) → tuple[str | None, int | None, str | None]¶

Split a string into path, id, and name components.

Respects single and double quoted substrings and backslash escapes. The ‘#’ and ‘?’ delimiters may appear in any order, but are expected to appear at most once each outside of quoted regions.

Query string must be of the form ‘name=<str>’ or ‘id=<int>’, where <str> may be a quoted string or an HTML percent-encoded string.

Fragment is a convenience for gracious interpretation of user input only. It must be an integer, a quoted string, or an HTML percent-encoded string. And if it’s a an integer, will be interpreted as an id; if it’s an string, will be interpreted as name. If it disagrees with the query field, a ValueError exception is thrown.

Locations are specified by standard http: https: or file: URLs, however the special notation “$<name>” looks up a DB in memory by it’s name alone as a user interface convenience.

Parameters:

s (str) – The string to split, e.g. a URL or path with query/fragment.

Returns:

A 3-tuple of (path, name, id). name is a str or None, id is an int or None.

Return type:

tuple[str, str | None, int | None]

Raises:

ValueError –

If the query or fragment cannot be parsed or one of the query fields doesn’t match the fragment field.

<validID> := <absoluteID> | <relativeID>

<absoluteID> := <existing-URL>{“?”<parameters>} | “#”<id>

<locationSpec> := <existing-URL> | “$”<dbName>

<parameters> := name=<name> | id=<int>

<relativeID> := {#}<id>

<id> := <int> | <str-without-whatespace> | <quoted-str>
