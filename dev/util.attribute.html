util.attribute module¶

  1. Objects are either TYPES or INDIVIDUALS

  1. A TYPE T is identified by T->ISTYPE->Type, an INDIVIDUAL I is identified by I->ISINSTANCE->Type

  2. A TYPE T can be marked as ABSTRACT, meaning A->ISINSTANCE->T is disallowd (eg: ISINSTANCE<:ISA:>ISTYPE)

  1. A<-ISTYPE<-X->ISINSTANCE->B is illegal

  2. ISA: TOP->ISA->TOP, ISTYPE: [TYPE<:TOP]->(ISTYPE<:ISA)->[TYPE], ISINSTANCE: [IND<:TOP]->(ISINSTANCE<:ISA)->[TYPE] seems hopelessly circular if 1.1

TYPE-ATTRIBUtES’ values can only be modified by TYPES (eg: fill-color) but the value is inherited by INDIVIDUALS

Individual-attributes are only non-TYPE-ATTRIBUTES because TYPES are also individuals (eg: name)

ROLE is an Attribute type that is covarient

non-ROLE Attribute types are invarient

Some VALUES are inherited (eg: color) and others are not (eg: name)

class util.attribute.RestrictionTypes(*values)¶

Bases: Flag

Restrictions on how an attribute is inherited, by individuals or by subtypes (see Restriction):

  • NOINHERIT: the key is inherited, but the value isn’t (a slot that must be filled locally).

  • NOOVERRIDE: the inherited value can’t be overridden.

  • PRIVATE: the key isn’t inherited at all; the attribute is invisible. It subsumes the other bits.

True iff the type typ argument is a valid type specification and value is None or a valid instance of typ.

A valid type is:

  • “choices[” <listOfStrings> “]”

  • a member of KNOWN_STRING_TYPES (“str”, “text”, “mtext”, “color”, “colour”)

  • a member of KNOWN_TYPES (“int”, “float”, “bool”, “str”, “text”, “mtext”, “color”, “colour”, “choices”, “list”, “dict”, “attrs”)

value, made the type typ says, if it isn’t already and it can be without losing anything: eg: 30 or “30” for a float is 30.0; 3.0 or “3” for an int is 3 (but 3.5 isn’t an int); “yes” or 1 for a bool is True; anything for a string type (“str”, “color”, …) is its text; “ a “ for “choices[a, b]” is “a”. class util.attribute.AttributedObject¶

Bases: Serializable, Dirtyable, strdict, Subject

An object with named Attribute objects, which inherits more from its supertypes (getSupers(), which subclasses must define), as their Restriction objects allow. get() finds a key’s effective value – the object’s own, or else the one it inherits; getLocal() and getInh() find only one or the other.

__setitem__(key: str, value: Serializable | int | float | bool | str | list | dict | strdict | tuple | set | None) → None¶
Parameters:

  • key (str) – The attribute name.

  • value (SerializableType) – The value to record under key.

Raises:

Can do one of 3 things:

  • if there is already a local attribute, its value is updated

  • if there is no local attribute but there is a super attribute, create a value-only attribute and associate that with key.

  • if there is no local attribute and no super attribute, create a complete (default) local attribute.

The value is first made the attribute’s type, if it can be (see coerceValue()). In all cases, this method will throw if the value does not pass validation checks.

keys() → KeysView¶
Returns:

A live, set-algebra-capable KeysView over this object’s LOCAL and INHERITED attribute keys.

Return type:

KeysView

Unlike plain dict.keys() (which reads the underlying storage directly and so would silently ignore inheritance), this is backed by __iter__()/__contains__()/__len__(), so it stays consistent with iter(self), key in self and len(self). As with a real dict.keys(), the view is live: it reflects later changes to this object (or its supers) rather than being a frozen snapshot, and supports set operations (&, |, -, ^) against other key sets/views.
